## 2. 待改进项（按优先级）

### P0 — 存量打标通路（本次审计核心发现）

现状证据链：
1. 新打标链路只覆盖**增量导入**（在线搜索、影视新闻两个入口）；库里 290 部存量 `MovieTags` 仍为 0 行，统计页类型分布、推荐标签权重、关系图谱、AI 摘要、去重完整度打分**五个下游对存量仍空转**。
2. 面向存量的补全入口有两个，**都不写标签**：
   - `MovieListView.xaml.cs:1306`（单部「获取信息」）——`info.Genres` 已拿到却丢弃；
   - `MovieListView.xaml.cs:1721-1766`（文件夹批量导入阶段 2）——同样只写 Director/Cast/Country 等。
3. `OmdbApiClient.ParseDetail`（`OmdbApiClient.cs:167-222`）**完全不解析 OMDb 返回的 `Genre` 字段**（形如 `"Action, Adventure, Sci-Fi"`），且缺英文类型→中文映射。
4. `CachedMovie` 实体无 Genres 字段 → cache.db 无法支撑离线回填。

为什么是 P0：豆瓣已封、TMDB API 被墙，**OMDb 是唯一不限流、1000 次/天的可达源**。补两点即可让存量 290 部在一天内逐步打标，零封禁风险：

| 改动 | 位置 | 工作量 |
|---|---|---|
| 解析 `Genre` 字段 + 英中映射表（Drama→剧情 等约 24 条） | `OmdbApiClient.ParseDetail` | ~30 行 |
| 两个存量补全入口落库处补标签写入（合并语义，不清用户已有标签） | `MovieListView.xaml.cs:1353` 与 `:1758` 附近 | ~15 行/处，`_tagService` 已持有（:42/:67）无需注入 |

语义注意：`SetTagsAsync` 是覆盖语义（`existingIds.Except(tagIds)` 会删），存量入口应改为「只增不减」的合并写入，避免冲掉用户手工维护的标签。
